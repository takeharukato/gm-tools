# gm-tools 共通仕様

本書は `gm-gather` と `gm-scatter` に共通する仕様および運用上の注意を集約した文書である。各コマンド固有の仕様は個別の仕様書を参照すること。

- [gm-gather 仕様](gm-gather-specJP.md)
- [gm-scatter 仕様](gm-scatter-specJP.md)

## 記法・方針

- 矢印表記は「 => 」(スペース=>スペース) で統一する (`→`は使用しない)。
- 読点は, 「, 」(カンマとスペース)を使用し, 句点は, 「。」を使用する。
- 用語は「終了コード」に統一する。
- 共有事項は本書に集約し, 個別仕様書から参照する方針である。

## ホストファイル形式

ホストファイルとは本ツールが操作対象とするリモートホスト群を列挙したファイルである。

- 1 行に 1 ホスト名または IP アドレスを記述する。
- 空行, `#` で始まる行, あるいはタブや空白に続く `#` 以降はコメントとして無視する。
- 既定パスは `hostfile` である。

### ホストファイルの例

```text
# サーバ群を示すコメント行
web01.example.com
web02.example.com    # 任意の注記 ( 例: 設置場所 )

10.0.0.15
```

上記各行の意味は次のとおりである。

- `# サーバ群を示すコメント行`: コメント行として読み飛ばす。
- `web01.example.com`: 完全修飾ドメイン名として解釈し, 1 ホストとして扱う。
- `web02.example.com    # 任意の注記 ( 例: 設置場所 )`: `#` 以降をコメントとして除外し, `web02.example.com` をホストとして扱う。
- 空行: コメントと同様に読み飛ばす。
- `10.0.0.15`: IPv4 アドレスをホストとして扱う。

## SELinux 対応ホストの判定基準

リモートホストが SELinux 対応とみなされる条件は以下のとおりである。

- selinuxfs が存在していること。すなわち `/sys/fs/selinux` が存在するか, 同等の確認が成功すること。
- `restorecon` コマンドが利用可能であること。`command -v restorecon` が成功する必要がある。

### SELinux 対応に必要なパッケージ

- RHEL/AlmaLinux/CentOS 系: `policycoreutils` に `restorecon` が含まれている。
- Debian/Ubuntu 系: `policycoreutils` に `restorecon` が含まれている。
- SELinux が無効化されているホストでは `--selinux=policy` はエラーとなり, `--selinux=auto` は処理を行わずに続行する。

## 終了コード策定方針

終了コードはプロセスの成否を示す値である。
本ツールは正常終了時は, `0`を返して終了する。
何らかの異常が発生した場合は, `0`以外の値を返して終了するか, Pythonの例外補足規定で規定された終了コードにより終了する。

具体的な返却値と各値の意味は, 個別仕様書で定義する。

## パス区切り文字の扱い

- パス区切り: SFTP 経路で用いるパス区切りは常に `/` である。リモート上でシェルを通じて操作する場合は各 OS 固有の区切り記号 ( Windows は `\`, Unix 系は `/` ) に従う。
- Windows ドライブレター (`X:/...`):
  - この形式は Windows の絶対パスとして扱う。
  - 非 Windows 環境でローカルパスとして指定するとエラーとなる。非 Windows ホストをリモート SRC として指定した場合は一致せずスキップされる。非 Windows 環境では `/...` または `~/...` を使用すること。
- Windows UNC (`\\\\server\\share\\...`):
  - Windows 上では絶対パスとして扱う。非 Windows 環境でローカル SRC に指定するとエラーとなる ( scatter のみ ) 。
  - レイアウト正規化: ローカルからリモートへ配置する際 ( scatter ) は `\\\\server\\share\\p` を `server/share/p` に変換し, `DEST/<rel>/...` を構成する。リモートからローカルへ保存する際 ( gather ) にリモート絶対パスが `//...` で始まる場合は, 先頭の空セグメントを `_` として保持する ( 例: `//a//b/` => `_/a/_/b` ) 。

## ホスト名とパス名を保存用表現へ変換する規則

- ホスト名の保存用表現:
  - 先頭が `.` の場合は `_` に置換する。
  - 英数字・ドット (`.`)・ハイフン (`-`)・アンダースコア (`_`) 以外の文字は `_` に置換する。
  - 区切り文字や制御文字など, ファイル名として不適切な文字は同様に `_` に置換する。
- リモート絶対パスの保存用相対表現:
  - 先頭のルート部分 ( `/` や `C:/` など ) を取り除いて相対化する。
  - 区切りは `/` に統一する。連続する `/` により空セグメントが生じた場合は `_` を 1 セグメントとして挿入する ( 例: `//a//b/` => `_/a/_/b` ) 。
  - Windows ドライブレターが含まれる場合は, 先頭要素のコロンを `_` に置換する ( 例: `C:/x/y` => `C_/x/y` ) 。
  - 各パス要素に含まれる英数字・ドット・ハイフン・アンダースコア以外の文字は `_` に置換する。

## 正規表現とチルダの解釈

### 正規表現の検出

`^$*+?{}[]\|()` のいずれかを含むパスは正規表現として扱う。`.` は検出対象のメタ文字には含めないため, `foo.bar` はリテラルとして扱う。

### ルート相対パス文字列

実際の絶対パス ( あるいは HOME を起点に絶対化したパス ) から先頭のルート部分 ( POSIX の `/`, Windows の `C:/`, UNC の `//server/share` など ) を除去し, 区切りを `/` に統一した文字列を本書では「ルート相対パス文字列」と呼ぶ。本ツールはこの文字列に対して正規表現を部分一致させ, マッチした項目を転送候補とする。

ルート相対パスへの変換例は以下のとおりである。

- POSIX (Linux/BSD など): `/var/log/a.log` => `var/log/a.log`
- Windows ドライブ: `C:/Windows/Logs/a.log` => `Windows/Logs/a.log`
- Windows UNC: `//server/share/dir/file.txt` => `server/share/dir/file.txt`
- HOME 起点 ( 相対指定を絶対化後 ) : `~/app/logs/x.txt` => `app/logs/x.txt`

### gm-gather / gm-scatter における解釈

- gm-gather ( SRC=リモート, DEST=ローカル )
  - SRC (リモート):
    - 絶対パス指定: `/...` は UNIX 絶対パス, `X:/...` や `X:\...` は Windows 絶対パスとして扱い, 内部的に `X:/...` 形式へ正規化する。
    - `~/`: `--user` で指定されたリモートユーザの HOME に展開する。`~` 単独や `~user` 形式は受け付けない。
    - 相対パス指定: リモート HOME を起点に結合する。`..` を含む指定は拒否する。正規表現メタ以降はそのまま保持する。
    - 正規表現評価: ルート以降のルート相対パス文字列に対して部分一致で評価する ( Python の `re.search` を利用 ) 。評価対象は通常ファイルである。メタ文字を含まないディレクトリをリテラル指定した場合は, その配下の通常ファイルを列挙する ( シンボリックリンクの扱いは `--follow-symlinks` の設定に従う ) 。
      - 区切り記号: リモート探索では正規表現中の区切り記号は常に `/` である ( Windows でも `C:/...` と `/` 区切りになる ) 。
      例: `var/log/.*\.log` は `var/log/a.log` ( Windows ホスト上の `var\log\a.log` ) に一致する。`var\\log\\.*\\.log` のような指定は無効である。
  - DEST (ローカル):
    - `~/`: ローカル実行ユーザの HOME に展開する。`~` 単独および `~user` 形式は拒否する。相対パス指定はカレントディレクトリを基準に絶対化する。
    - 保存レイアウト: `DEST/<ホスト名の保存用表現>/<ルート相対パスの保存用表現>` に配置する ( 例: `C:/x/y` は `C_/x/y` ) 。
- gm-scatter ( SRC=ローカル, DEST=リモート )
  - SRC (ローカル):
    - 絶対パス指定: `/...` はローカル絶対パスであり, `X:/...` は Windows 実行環境でのみ有効である。非 Windows 環境で指定するとエラーとなる。
    - `~/`: ローカル実行ユーザの HOME に展開する。`~` 単独および `~user` 形式は拒否する。
    - 相対パス指定: カレントディレクトリを基準に絶対化する。
    - 正規表現評価: ルート相対パス文字列に対して部分一致で評価する ( Python の `re.search` を利用 ) 。正規表現モードでは通常ファイルを列挙する。メタ文字を含まない指定で実体が存在する場合はそのパス ( ファイルやディレクトリ ) を候補とする。`--pack` を使わない場合はディレクトリは転送対象から除外される。
      - 区切り記法: ローカル探索では OS の区切り記号を用いる ( Linux/macOS は `/`, Windows は `\` ) 。Windows では正規表現中も `\` 区切りで記述する。例: `foo\.*` は `foo\a.txt` に一致し, `bar\a.txt` には一致しない。
  - DEST (リモート):
    - 絶対パス指定: `/...` および `X:/...` を絶対パスとして受理する。
    - `~/`: `--user` で指定したリモート HOME に展開する。`~` 単独および `~user` 形式は拒否する。
    - 相対パス指定: リモート HOME を起点に解決する。
- パス区切り記号: リモート探索 ( SFTP 経路 ) では OS に関係なく `/` 区切りで評価する。`--pack` を使用した場合でも, 正規表現が参照するルート相対パス文字列は `/` 区切りに正規化して評価する。実際の絶対パス表記は経路によって OS 依存の区切りになる場合があるが ( 例: Windows の `--pack` + sudo では `C:\...` ) , 正規表現の評価は常に `/` 区切りで行う。ローカル探索は OS の区切り記号に従う ( Linux/macOS は `/`, Windows は `\` ) 。

## 候補列挙 ( 探索経路と対象範囲 )

本節は正規表現やチルダ展開の後にどのパスが転送候補となるかを示す共通挙動である。

- 走査経路:
  - `--pack` を指定し, リモート側で権限昇格を伴う列挙が有効な経路では, リモート上でルート配下を走査し, ルート相対パスに対して正規表現を部分一致させる ( Python の `re.search` を利用 ) 。
  - その他の経路では SFTP を用いてルート配下を走査し, 同様に部分一致で評価する。
- ディレクトリをリテラル指定した場合 ( メタ文字なしで SRC がディレクトリのとき ) :
  - その配下にある通常ファイルを列挙し, ディレクトリ自身は候補に含めない。
- シンボリックリンク ( ファイルへのリンク ) の候補化:
  - `--pack` 未指定: 候補に含めない ( 通常ファイルのみ ) 。
  - `--pack` 指定: リンク自体を候補に含める。実際の転送内容は後述の転送方式で定まる。
- ディレクトリへのシンボリックリンク:
  - SFTP の型判定でディレクトリと判断された場合は配下を走査する場合がある。特別扱いは行わない。
- 非対象:
  - デバイス, FIFO, ソケットなどの特殊ファイルは候補に含めない。

## 転送方式の詳細 ( SFTP 逐次と pack )

- SFTP 逐次 (`--pack` 未指定):
  - 対象: 候補のうち通常ファイルのみを 1 件ずつ転送する。
  - 非対象: ディレクトリ, シンボリックリンク, デバイス, FIFO, ソケットなどは転送しない。
- pack (`--pack` 指定, リモートでアーカイブを作成して一括転送):
  - 収集単位: ホストごとに 1 度だけアーカイブの生成・受信・展開を行い, ローカルで通常ファイルを復元する。
  - ディレクトリ: 展開時に必要なディレクトリを作成する。親ディレクトリにシンボリックリンクが含まれる場合は安全のためスキップする。
  - シンボリックリンク ( ファイルへのリンク ) の扱い:
    - `--follow-symlinks` を指定しない場合: リンクはアーカイブ内でリンクとして扱い, ローカル展開ではファイルを生成しない。リンクのみが一致した場合は何も出力されない。
    - `--follow-symlinks` を指定した場合: tar コマンドが対応していればリンク先の実体を取り込み, ローカルでは通常ファイルとして復元する。対応していない環境では従来どおりリンクとして扱い, ローカルには生成されない。

### pack 時におけるハードリンクの扱い

- GNU tar がハードリンク情報を記録している場合はローカル展開時に通常ファイルとして復元する ( デマテリアライズ ) 。
- 復元手順:
  - すでに抽出されたソースファイルが存在する場合はその内容を複製して通常ファイルを作成する。
  - 未抽出の場合でもアーカイブ内に同名の通常ファイルがあればその内容を複製する。
  - いずれも不可能な場合は警告を出してスキップする。
- 復元に成功した件数は抽出件数として加算する。

## シグナルと協調停止 ( Graceful Stop )

本ツールは SIGINT や SIGTERM を受信すると協調停止処理に移行する。協調停止では安全な中断点で処理を停止し, 以降のホストやファイルの転送を中止し, ローカルおよびリモートに作成した一時ファイルの削除を試みる。併せて, それまでの進捗に基づき終了時の集計を実施する。

## 出力ログ仕様

### ログの書式

本ツールが出力するログは以下の形式である。

```text
<timestamp> level=<level> host=<host> op=<op> phase=<phase> trial=<n> processed=<n> total=<n> [warnings=<n>] [errors=<n>] [duration=<sec>] [seq=<n>]
```

`timestamp`, `level`, `host`, `op`, `phase`, `trial`, `processed`, `total` を固定の順序で出力し, 必要に応じて `warnings`, `errors`, `duration`, `seq` を後続に追加する。ログはホスト単位で集約して出力されるため, 並列実行中でも行の順序や整形が崩れない。

#### 各キーの意味と例

- `timestamp`: ISO-8601 形式の日時。タイムゾーンとミリ秒を含む。例: `2025-11-19T12:10:00.000+09:00`
- `level`: ログレベル。
  - `DEBUG`: 詳細情報。標準出力に出力する。例: `processing` 行。
  - `INFO`: 通常情報。標準出力に出力する。例: `host start`, `host done`, `summary`。
  - `WARNING`: 警告。標準エラー出力に出力する。
  - `ERROR`: エラー。標準エラー出力に出力する。
  - `CRITICAL`: 致命的エラー。標準エラー出力に出力する。
- `host`: 対象ホスト名。
  - ホスト別ログでは対象ホスト名 ( 例: `db01` ) を出力する。
  - 集計ログでは `-` を出力し, 全体集計であることを示す。
- `op`: 操作種別。`gather` はリモートからローカルへの収集, `scatter` はローカルからリモートへの配布を示す。
- `phase`: フェーズ。
  - `start`: ホスト処理の開始を示す。
  - `processing`: ホスト処理が進行中であることを示す。
  - `done`: ホスト処理が完了したことを示す。
- `trial`: 当該ホストで行った試行件数 ( 成功・失敗を含む ) 。開始時は 0 であり, 処理が進むにつれて増加する。完了行では計画件数と一致する。例: `356`
- `processed`: その時点までに完了した件数。例: `220`
- `total`: 当該ホストに割り当てられた総件数。例: `356`
- `warnings`: 警告件数。完了行や集計行で表示される。例: `1`
- `errors`: エラー件数。完了行や集計行で表示される。例: `0`
- `duration`: ホスト処理に要した秒数。完了行にのみ表示し, 集計行には表示しない。例: `8.2`
- `seq`: ログ行の通番。`--verbose` 指定時の進行行にのみ表示する。

##### ホスト完了行の扱い

ホスト完了行とは特定ホストの処理が終わった時点で出力される INFO ログを指し, `phase` は `done`, `host` は対象ホスト名となる。`warnings`, `errors`, `duration` の各値が併記され, 当該ホストに関する最終結果を示す。

##### 集計行 (`summary`) の内容

集計行は全ホストの処理が完了した直後に 1 回だけ出力される INFO ログである。内容は以下のとおりである。

- 出力タイミング: 全ホスト処理終了後。
- `level`: `INFO`。
- `host`: `-`。
- `op`: 実行した操作種別 ( `gather` または `scatter` ) 。
- `phase`: `done`。
- `trial`: 全ホストの試行件数の総和。
- `processed`: 全ホストの処理件数の総和。
- `total`: `trial` と同じ値。
- `warnings`: 全ホストの警告件数の総和。
- `errors`: 全ホストのエラー件数の総和。
- `duration`: 出力しない。
- `seq`: 出力しない。
- `msg`: `summary`。

### ログ出力例

```text
2025-11-19T12:10:00.000+09:00 level="INFO" host="db01" op="scatter" phase="start" trial="0" processed="0" total="356" msg="host start"
2025-11-19T12:10:02.345+09:00 level="DEBUG" host="db01" op="scatter" phase="processing" trial="10" processed="128" total="356" seq="5" msg="processing"
2025-11-19T12:10:08.200+09:00 level="INFO" host="db01" op="scatter" phase="done" trial="356" processed="356" total="356" warnings="1" errors="0" duration="8.2" msg="host done"
2025-11-19T12:10:08.250+09:00 level="INFO" host="-" op="scatter" phase="done" trial="356" processed="356" total="356" warnings="1" errors="0" msg="summary"
```

## メッセージのローカライズ方針

- 利用者向けのヘルプや警告・エラーメッセージはローカライズ対象である。
- 構造化ログのキーおよび `msg` の語句 ( `host start`, `processing`, `host done`, `summary` など ) はローカライズしない。キーの並び順も固定である。

### 翻訳更新手順

翻訳更新時は次の手順を踏むこと:

  1. トップディレクトリで, `make -C po update-po`を実行し, poファイルを更新する。
  2. `po/gm-tools.pot` と `po/*.po` の差分を確認して反映する
  3. `msgfmt --check poファイル名`を実行してフォーマットエラーがないことを確認する (例: `msgfmt --check po/ja.po`)
  4. `msgfmt --statistics poファイル名`を実行して, 各poファイル内の未翻訳 (`untranslated`)の件数, ファジー訳(`fuzzy`)の件数が`0`であることを確認する (例: `msgfmt --statistics po/ja.po`)

## CLI オプション共通化ガイドライン

- 新しいオプションを追加する場合は, 共通ヘルパーへ定義を集約しつつ, 既存 CLI の文言が変わらないようにする。
- コマンド間で共通したオプションは `gm_tools.core_cli_support.add_common_cli_options()` を利用して追加する。
- ショートオプションとロングオプションの名称の双方が一致し, かつ, コマンド毎に動作, 挙動が異なるオプションについては, `gm_tools.core_cli_support.add_common_cli_options()`の`help_overrides` 引数(`dest` 名をキーとしたヘルプ文言の上書き辞書。)のキー `dest` 名 ( 例: `dry_run` ) を指定し, ヘルプの文言を上書きする。

## 依存パッケージ

### ローカルホスト ( 実行環境 )

- Python ライブラリとして `paramiko` を利用する。

OS パッケージからの導入例を以下に示す。

```shell
# RHEL/AlmaLinux/Rocky
sudo dnf install -y python3-paramiko

# Debian/Ubuntu
sudo apt-get update && sudo apt-get install -y python3-paramiko
```

pip から導入する場合は以下のとおりである。

```shell
# 単体インストール
python3 -m pip install --user paramiko

# requirements.txt を用いる場合 (ファイルに "paramiko" を記載)
python3 -m pip install -r requirements.txt
```

### リモートホスト ( 必要に応じて )

- `tar` ( GNU tar 推奨 ) が必要である。
- `setfacl` ( ACL 復元に必要 ) が必要である。
- `setfattr` ( xattr 復元に必要 ) が必要である。
- `restorecon` ( SELinux ラベル再適用に必要 ) が必要である。
