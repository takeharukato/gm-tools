# gm-scatter 仕様

本書は `gm-scatter` コマンドの実際の挙動を権威仕様として記述する。共通仕様や用語は `docs/common-spec.md` を参照のこと。

- `SRC...` : 1 つ以上のローカルパスまたはパターン。
- `DEST`   : リモートホスト上の配置先ディレクトリ。必須。

### 位置引数

| 引数 | 説明 |
| ---- | ---- |
| `SRC...` | ローカル側の送信元。リテラル/正規表現/チルダ展開の規則は「パスと正規表現仕様」を参照。最低 1 件必要。 |
| `DEST` | リモート側の配置先。相対指定はリモートでのターゲットユーザのホームディレクトリを基準に解決する。`~` や `~user` 形式は無効。 |

### オプション一覧 (man スタイル)

| オプション | 説明 |
| ----------- | ---- |
| `-H`, `--hosts` *FILE* | ホストリストを記載したファイルを指定。既定ではカレントディレクトリの `hostfile` を読み込み、空行・行頭 `#`・行末コメントを無視する。 |
| `-u`, `--user` *USER* | リモートでファイルを配置すべきユーザ。既定はローカル実行ユーザ。SELinux や sudo の判定はこのユーザを基準に行う。 |
| `-s`, `--ssh-user` *USER* | SSH 接続に使用するユーザ。省略時は `--user` と同じ。`--pack` 時に sudo を使うかどうかの自動判定に影響する。 |
| `-P`, `--port` *PORT* | SSH ポート番号。既定は 22。 |
| `-K`, `--key` *PATH* | SSH 秘密鍵ファイル。未指定時は Paramiko の既定検索パスを使用。 |
| `-W`, `--password` *PASS* | SSH パスワード。シェル履歴に残る可能性があるため鍵認証が推奨される。 |
| `-T`, `--timeout` *SEC* | SSH セッションおよびリモートコマンドのタイムアウト秒。既定は 30 秒。 |
| `-S`, `--strict-host-key-checking` | 未知のホスト鍵を拒否し、known_hosts に登録されていないサーバーへは接続しない。省略時は未知の鍵を自動登録する。 |
| `-j`, `--parallel` *N* | ホスト単位の並列数。1 未満を指定しても 1 に切り上げられ、既定値は 4。 |
| `-n`, `--dry-run` | 転送を行わずに計画の作成とログ集計のみ実施する。常に終了コード 0。 |
| `-v`, `--verbose` | 追加のデバッグログを有効化。dry-run 時も同様に適用される。 |
| `--pack` | ローカルで一時的な tar.gz を作成し、1 度のアップロードでまとめて展開する。省略時は SFTP で逐次転送する。 |
| `--follow-symlinks` | `--pack` 使用時にローカルのシンボリックリンクを辿って実体を取り込む。SFTP モードでは無視される。 |
| `-x`, `--sudo-extract` | `--pack` 経路でリモートの `mkdir`、tar 展開、既存ファイルの上書きを常に `sudo -n` で実行する。`--no-sudo-extract` で明示的に無効化できる。指定しない場合は自動判定。 |
| `--selinux` *MODE* | `auto` / `policy` / `ignore`。`--pack` 使用時の SELinux ラベル復元方針。既定は `auto`。SFTP モードでは効果がない。 |

### オプション詳細

- SSH 接続は Paramiko で確立し、プログラム終了まで同じセッションを再利用する。鍵ファイルやパスワードは Paramiko に直接渡す。
- `--timeout` の値はリモートのホームディレクトリ確認、一時アーカイブ展開、sudo コマンド実行など、すべてのリモート操作で共通のタイムリミットとして利用される。
- `--pack` を指定すると、ホスト単位で一度だけローカル側に tar.gz を生成し、それをアップロードして `DEST` 直下に展開する。SFTP モードでは送信対象ごとに逐次アップロードを行う。
- `--follow-symlinks` は `--pack` と組み合わせた場合のみ効果があり、対応する tar コマンドがあればリンク先の実体を取り込む。SFTP モードではシンボリックリンクは常に除外される。
- `--sudo-extract` と `--no-sudo-extract` をどちらも省略した場合、`--pack` を使っていて SSH ログインユーザと配置対象ユーザが異なるときだけ自動的に `sudo -n` を有効にする。
- SFTP モードでも、SSH ログインユーザと配置対象ユーザが異なる場合は親ディレクトリの作成だけ sudo を使って行い、ファイルの書き込み自体は SSH ログインユーザの権限で実施する。
- `--selinux` は `--pack` を使うときだけ評価され、`auto` や `policy` に設定すると SELinux の復元処理が走る。`ignore` を選ぶと常にスキップする。
- `--dry-run` はローカルで送信候補を列挙し、ホスト別の件数集計を行ったあと、実際の転送を行わずに終了する。

## パスと正規表現仕様

- `SRC` はローカルのパスを前提とし、次のように解釈する。
  - `/...` : UNIX 系の絶対パス。転送計画を作る際にそのまま絶対パスとして扱い、リモートでは先頭のスラッシュを取り除いた形で相対パスに変換する。
  - `X:/...` や `X:\...` : Windows のドライブ絶対パス。ドライブ文字の後はスラッシュ区切りに整形して扱い、Linux 上で実体が存在しない場合は対象から除外する。
  - `~/...` : コマンドを実行しているローカルユーザのホームディレクトリに展開する。
  - 相対パス : 実行時のカレントディレクトリを基準に絶対パスへ変換する。`..` を用いてカレントより上の階層へ出ようとするとエラーとして該当パターンを除外する。
  - `~` 単独、`~user`、`~user/...` は無効であり、「bare tilde is not allowed」「tilde with username is not supported」を表示して終了する。
- 正規表現を判定するときは `^` や `[]` などの記号を手掛かりにし、`.` のみでは正規表現扱いにならない。
- 正規表現として扱う場合は、記号が現れる直前までを走査起点とし、その配下のファイル名をスラッシュ区切りの相対パスとして正規表現に照合する。マッチしたファイルやディレクトリが転送候補に追加される。
- リテラルで指定したパスが存在しない場合は警告を出さずに対象から外す。同じ場所を繰り返し指定しても一度だけ扱う。
- `--pack` 使用時は、ローカルでディレクトリを指定した候補に末尾スラッシュを付けて tar 作成時のディレクトリ扱いを明示する。正規表現で一致した結果はそのまま扱う。

## SRC と DEST の解釈とレイアウト

- `DEST` の解釈は次の通り。
  - `/...` : リモートの絶対パスとしてそのまま使用する。
  - `X:/...` や `X:\...` : Windows のドライブ絶対パスとして扱い、アップロード先の基準とする。
  - `~/...` : リモートのターゲットユーザのホームディレクトリに展開したうえで結合する。
  - 相対パス : リモートのターゲットユーザのホームディレクトリ配下に配置される。
  - `~` や `~user` の形式は無効で、位置引数エラーとして終了する。
- 送信元のパスは、リモート側では `/` 区切りの相対経路に変換される。絶対パスは先頭のスラッシュを除去し、Windows のドライブは `C/...` のような形に整形する。相対パスは指定したとおりの構造を維持する。
- 正規表現でマッチした結果は、走査起点からの相対パスを保ったまま `DEST` に配置される。パストラバーサルの危険があるパス (`..` や先頭 `/`) は正規化の過程で除去され、最終的に安全なパスだけが残る。正規化後に空文字になった場合は元ファイル名を使用する。
- すべてのホストで同じ `DEST` を使用し、ホストごとのサブディレクトリは作らない。つまり、すべてのホストに対して `DEST/相対パス` が直接書き込まれる。

## 転送方式

### SFTP 逐次 (既定)

- 送信候補ごとに SFTP の `put` を呼び出してファイルをアップロードする。ディレクトリはローカルで走査し、中身のファイルを一つずつ送る。リモートでは必要に応じて `mkdir -p` を実行して親ディレクトリを作成する。
- SSH ログインユーザと配置対象ユーザが異なる場合、親ディレクトリの作成だけ `sudo -n mkdir -p` で行う。それ以降のファイル書き込みは SSH ログインユーザの権限のままであり、書き込み権限がないと即座にエラー扱いとなる。
- 新規作成されるファイルやディレクトリの所有者は SSH ログインユーザで、パーミッションはリモート側の umask に左右される。SELinux ラベルや ACL、拡張属性はこの経路では復元されない。
- 既存ファイルを上書きする場合、親ディレクトリ作成に sudo を使っているときだけ、上書き前に所有者・グループ・アクセス権・ACL・拡張属性を取得し、アップロード後に復元を試みる。対応するツールがリモートに無い場合や復元に失敗した場合でも転送は継続する。
- シンボリックリンクは常に転送対象から除外され、ログには「リンクを無視した」旨が記録される。

### `--pack`

- 各ホストについて最初の転送候補を処理するときだけ、ローカル側で送信対象を一括して tar.gz にまとめる。重複指定や親子関係はこの時点で整理される。
- 生成したアーカイブは SFTP でリモートの一時ディレクトリへアップロードする。アップロード後にリモート側でアーカイブを展開し、`DEST` の下へファイルを配置する。
- tar コマンドの種類を自動判定し、対応するオプションで展開する。新規作成と既存ファイルの上書きを分け、既存ファイルは安全な一時ディレクトリに展開してから最終位置へ移動することで部分書き換えを防ぐ。
- 上書きの際は、可能であれば事前に所有者・グループ・アクセス権・ACL・拡張属性・更新時刻を記録しておき、`sudo-extract` が有効であれば同じ値に戻す。新規ファイルやディレクトリについても sudo を使って `chown` し、ターゲットユーザおよびその主要グループに揃える。
- `--follow-symlinks` が有効な場合、シンボリックリンクはリンク先の実体をアーカイブに含める。無効な場合はアーカイブにも含めない。親ディレクトリがシンボリックリンクだった場合は展開時に警告を出し、その項目をスキップする。
- 展開後は `restorecon` を用いた SELinux ラベル復元や一時ファイルの削除を行う。sudo を使用する設定であれば、これらの処理も `sudo -n` を通じて実行される。

## 転送対象の相違

| 項目 | SFTP | `--pack` |
| ---- | ---- | -------- |
| 通常ファイル | 各ファイルを個別にアップロード。既存ファイルは必要に応じて所有者や権限を復元。 | アーカイブ展開時にまとめて配置。既存ファイルは一時領域経由で上書きし、所有者や権限を復元。 |
| ディレクトリ | ローカルを走査して必要なディレクトリを作成。属性の復元は行わない。 | 展開時に自動作成。sudo を使用していればターゲットユーザに合わせて所有者を設定。 |
| シンボリックリンク | 常に転送対象外。ログで無視したことを記録。 | `--follow-symlinks` 有効時のみリンク先の実体を取り込む。無効時は除外。 |
| ハードリンク | ハードリンク情報は保持されず、個別のファイルとして配置。 | GNU tar の情報を利用して通常ファイルとして再現する。 |
| デバイス/FIFO/ソケット | 送信候補から除外。 | アーカイブへ含めず、展開時の安全チェックでも拒否。 |
| ACL/xattr | 親ディレクトリ作成に sudo を使っており、かつ必要なツールがある場合のみ既存ファイルで復元。 | `--sudo-extract` が有効で必要なツールが存在する場合に既存ファイルで復元。新規はデフォルトのまま。 |

## --follow-symlinks の挙動

- フラグ未指定時
  - SFTP: ローカルのシンボリックリンクは検出した時点で転送対象から外し、リンク自体もアップロードしない。
  - `--pack`: アーカイブの作成段階でシンボリックリンクを除外し、リモートにも配置しない。
- フラグ指定時
  - SFTP: 挙動に変化はなく、シンボリックリンクは依然として転送しない。
  - `--pack`: アーカイブ作成時にリンク先を実体として含め、リモートでは通常のファイルやディレクトリとして展開する。親ディレクトリがシンボリックリンクだった場合は展開時に警告が出て該当項目が除外される。

## sudo の利用条件

- `--pack` を使用する場合、`--sudo-extract` を明示すると常に `sudo -n` で tar 展開や上書きを行う。`--no-sudo-extract` を指定すると常に sudo を使わない。どちらも指定しない場合は、`--pack` かつ SSH ログインユーザと配置対象ユーザが異なるときにだけ自動で sudo を使う。
- sudo を使う設定では、リモート側での `mkdir -p`、tar 展開、既存ファイルの上書き、所有者変更、アクセス権変更、ACL/xattr の復元、SELinux ラベルの再設定、一時ファイル削除といった操作がすべて sudo 経由で実行される。
- SSH ログインユーザと配置対象ユーザが異なる場合、SFTP モードでも親ディレクトリの作成だけ sudo を利用する。ファイル内容のアップロード自体は sudo を介さないため、書き込み権限が無いと転送に失敗する。
- ローカル側で sudo を実行する処理は存在しない。

## SELinux 対応

### SELinux 利用可否の判定

`gm-scatter` はリモートホストにおいて、SELinux の仮想ファイルシステムがマウントされているか、あるいは `restorecon` コマンドが利用可能かを確認する。いずれかが欠けている場合は SELinux ラベルの復元を行わない。

### `--selinux` オプションの挙動

- `ignore` : どのホストでも SELinux の復元処理を実施しない。
- `auto` (既定) : SELinux 関連の要件を満たすホストでのみ `restorecon -RF` を実行し、非対応ホストでは黙ってスキップする。
- `policy` : 対応要件を満たさないホストではエラーとして転送を失敗させる。対応ホストでは `restorecon -RF` を必ず実行する。
- 処理対象は `--pack` で新規作成または更新されたファイルと空ディレクトリであり、既存ファイルを上書きした場合も対象に含める。SFTP モードでは `restorecon` を呼び出さない。

## メタデータ復元条件

- 所有者・グループ・パーミッション
  - SFTP: 親ディレクトリ作成に sudo を使用している場合に限り、既存ファイルの上書き時に所有者やアクセス権を復元する。必要なツールが無い場合や復元に失敗した場合でも転送自体は継続する。新規ファイルは SSH ログインユーザ所有で作成される。
  - `--pack`: `--sudo-extract` が有効なら、既存ファイルで記録した所有者やアクセス権を復元し、新規ファイル・ディレクトリについてもターゲットユーザとその主要グループに合わせて `chown` する。sudo を使わない設定では復元を行わない。
- タイムスタンプ
  - SFTP: Paramiko の既定動作に従い、更新時刻の保持は保証されない。
  - `--pack`: 上書き対象についてアーカイブ内の更新時刻を利用して `touch -r` を実行し、元と同じ mtime に合わせる。失敗しても転送は中断しない。
- ACL と拡張属性
  - どの経路でも、リモートに `getfacl`/`setfacl` や `getfattr`/`setfattr` が無い場合は取得・復元を行わない。
  - SFTP: 親ディレクトリ作成に sudo を使用しており、必要なツールが存在する場合に限り、既存ファイルの ACL/xattr を復元する。新規作成では実行しない。
  - `--pack`: `--sudo-extract` が有効で必要なツールが存在するときに既存ファイルの ACL/xattr を復元する。新規ファイルではデフォルト値のままとなる。
- SELinux コンテキスト
  - `--pack` 経路で `--selinux` が `auto` または `policy` の場合、条件を満たしたホストでは `restorecon` により再設定する。
  - SFTP 経路では SELinux ラベルの変更を行わない。

## 並列処理 (`--parallel`)

- ホスト単位でスレッドを割り当て、最大でも指定した並列数だけ同時に処理する。値が 1 未満でも 1 に切り上げられる。各ホスト内のファイル転送は逐次で行う。
- 進行状況はホスト別に集計され、処理した件数やエラー有無がログへ記録される。途中で中断要求があった場合は共有の中断フラグがセットされ、新たなホスト処理の開始を停止する。

## ログ・エラーメッセージ・終了コード

代表的なメッセージと終了コードは次の通り (メッセージは gettext で翻訳される)。

| メッセージ (msgid) | 発生条件 | 終了コード |
| ------------------- | -------- | ---------- |
| `"At least one SRC and a DEST are required."` | 位置引数が不足している。 | 4 |
| `"bare tilde is not allowed"` | `SRC` または `DEST` に `~` を単独で指定した。 | 4 |
| `"tilde with username is not supported"` | `SRC` または `DEST` に `~user` 形式を指定した。 | 4 |
| `"No hosts found in hosts file."` | ホストファイルに有効なホストが存在しない。 | 1 |

- 転送中にエラーが発生した場合はホスト単位の集計でエラー件数が 1 以上と記録され、プロセスの終了コードは 2 になる。
- `--dry-run` で計画だけ作成した場合は常に終了コード 0 を返す。

## シグナル受信時の動作

- SIGINT や SIGTERM を受信すると中断フラグが立ち、新しいホストの処理を開始せず、進行中の転送処理にはキャンセルを通知する。
- 中断が発生すると `"Interrupt requested; cancelling remaining transfers (some remote hosts may see partial files or directories)."` という警告ログを出力し、完了状況に応じて終了コード 0 または 2 を返す。
- 終了時にはリモートの一時ディレクトリやローカルの一時ファイルを削除し、SSH/SFTP セッションを閉じ、最後に集計結果を出力する。部分的なアップロードが残る可能性があるため、再実行時はリモート側の整合性を確認することが推奨される。

## 制限と注意事項

- 正規表現は Python `re` の仕様に従うため、`\w` などの文字クラスはロケールに依存する場合がある。必要に応じて明示的なフラグを利用すること。
- `--pack` を使うにはローカルに Python の `tarfile` モジュールが読み込めること、リモートに `tar`・`gzip`・`mktemp`・`bash` がインストールされていることが必要。欠けていると tar コマンドの検出や事前チェックでエラー終了する。
- `--follow-symlinks` は `--pack` と併用したときのみ意味があり、リンク先が存在しない場合はアーカイブの作成段階で自動的に除外される。
- `--password` はコマンドラインに平文で残るため、鍵認証の利用とシェル履歴の扱いに注意すること。
- SFTP モードではリモート側の umask や既存ファイルの権限により結果が変わる。正確な権限復元が必要なら `--pack` と sudo を組み合わせることを検討する。
- SELinux ラベルの復元は `--pack` 経路でのみ行われ、SFTP モードではラベルが変わらない場合でも整合性の保証はない。
- ACL や拡張属性の復元は必要なツールがインストールされている場合に限り可能で、存在しなくても転送は続行される。
- 環境変数 `GM_SCATTER_DEBUG=1` を設定すると詳細ログが出力されるが、出力量が多いため本番運用では推奨されない。
- 中断が発生すると `"Interrupt requested; cancelling remaining transfers (some remote hosts may see partial files or directories)."` を WARN ログに記録する。
