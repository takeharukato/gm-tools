# gm-gather 仕様

実装を唯一の権威として記述しています。共通事項 (ログ仕様、ホストファイル、終了コードの概念 など) は [common-spec.md](./common-spec.md) を参照してください。

## 概要

複数ホストからリモートファイルを収集し、ローカルの `DEST/<SANITIZED_HOST>/...` に保存します。収集方式は次の 2 通りです。

1) 逐次 SFTP (デフォルト) => 通常ファイルを 1 件ずつ取得
2) リモート圧縮収集 (`--pack`) => リモートで tar.gz 作成 => 1 回ダウンロード => ローカルで安全展開

## 使い方 (シノプシス)

```plaintext
gm-gather [SRC ...] DEST

SRC:
  - '/...': リモートの絶対パス (UNIX)
  - 'X:/...': リモートの絶対パス (Windows)
  - '~/...': `-u/--user` の HOME を起点として展開
  - '~'   : 受け付けません (終了コードは無効引数)
  - RELATIVE: `-u/--user` の HOME 相対として扱う ( '..' による HOME 脱出は拒否 )
  先頭ルート以降は「パス正規表現」として扱い、`/` 区切りの相対名に対して部分一致で評価します（Pythonの`re.search`で評価します）。

DEST:
  ローカル保存先ディレクトリ。相対はカレントから絶対化。`~` や `~user` 形式はエラー。
  -H, --hosts FILE           ホストファイル (既定: hostfile)
  -u, --user USER            リモート上のターゲットアカウント (既定: 実行ユーザ)
  -s, --ssh-user USER        SSH ログインユーザ (既定: --user と同じ)
  -P, --port PORT            SSH ポート (実装既定)
  -K, --key PATH             秘密鍵
  -W, --password PASS        パスワード
  -T, --timeout SEC          SSH/コマンドのタイムアウト秒
  -S, --strict-host-key-checking  厳格なホスト鍵検証
  -j, --parallel N           ホスト並列数 (既定: 4)
  -n, --dry-run              計画のみ表示 (転送なし)
  -v, --verbose              詳細ログ
      --pack                 リモートで tar.gz 作成 => ダウンロード => ローカル展開
      --follow-symlinks      `--pack` 時: シンボリックリンクを参照先に解決してアーカイブを作成
  -x, --sudo-collect / --no-sudo-collect
                             収集時に sudo を使用 (pack 経路のみ)。省略時は auto
```


## SRC の解釈と列挙

- HOME 相対 (RELATIVE) は `-u/--user` の HOME に連結して絶対化します。先頭ルート部以降は正規表現として評価します。
- ディレクトリをリテラルで与えた場合は、その直下を含む配下の「通常ファイル」を列挙します（正規表現は適用しません）。
- `~user/...` 形式は明示エラーにします（終了コード参照）。
- Windows 形式の絶対パス `X:/...`（および必要に応じて UNC `\\server\\share\\...`）もリモートの絶対として扱います。詳細は共通仕様の「プラットフォーム注記」を参照してください。

- 保存先は常に `DEST/<SANITIZED_HOST>/<remote_abs_without_leading_slash>` に保存します。
- `<SANITIZED_HOST>` は英数・ドット・アンダースコア・ハイフン以外を `_` に置換し、先頭の `.` は除去します。

## 収集方式の詳細

- 逐次 SFTP:
  - 所有者/グループ/ACL/xattr の保持は行いません。mtime は取得時刻になる場合があります。
- `--pack`:
- 逐次 SFTP:
  - 通常ファイルを 1 件ずつ SFTP で取得。ディレクトリは収集対象に含めません。シンボリックリンクは対象外です。
- `--pack`:
  - リモートで tar.gz を作成 => 1 回ダウンロード => ローカルで安全展開。

## sudo-collect の挙動（三値）

- 指定方法と既定:
  - 省略（auto）: `--ssh-user` と `--user` が異なる場合のみ有効になります。それ以外は無効です。
  - `--sudo-collect`（強制オン）: 常に有効にします。
  - `--no-sudo-collect`（強制オフ）: 常に無効にします。

- 影響範囲:
  - リモート側の候補列挙と `--pack` 時のアーカイブ作成・削除にのみ影響します。SFTP による個別転送そのものには影響しません。
  - 有効時は、権限昇格下での走査/アーカイブ作成が可能になり、指定ユーザーでは到達できないパスが収集対象に含まれることがあります。無効時は、指定ユーザー権限でアクセス可能な通常ファイルに限定します。

## 候補列挙（リモートの探索経路と含まれる対象）

本節は、`gm-gather` における「SRC の解釈後に、どのパスを候補として列挙するか」の挙動を示します（正規表現/チルダ展開は共通仕様の規則に従います）。

- 走査経路の選択:
  - `--pack` と `--sudo-collect`（有効）の併用時: リモート上でルート配下を走査します。ルート相対パスに正規表現を部分一致で適用します（Python の `re.search`）。ディレクトリのシンボリックリンクは走査対象にしません（リンク先ディレクトリ配下は探索しません）。
  - 上記以外（非 `--pack`、または `--pack` だが `--sudo-collect` 無効）: SFTP でルート配下を走査します。ルート相対パスに正規表現を部分一致で適用します（Python の `re.search`）。ファイルに対するシンボリックリンクは `--pack` の有無に応じて取り扱いが変わります（後述）。ディレクトリへのシンボリックリンクは、型判定によりディレクトリとして見える場合があり、その場合は配下を走査することがあります。

- ディレクトリのリテラル指定（メタ無しで SRC にディレクトリを与えた場合）:
  - そのディレクトリ配下の「通常ファイル」を候補として列挙します。ディレクトリ自身は候補に含めません。

- シンボリックリンクの候補化（ファイルへのリンク）:
  - `--pack` 未指定: 候補に含めません（通常ファイルのみ）。
  - `--pack` 指定時: リンクそのものを候補に含めます。`--follow-symlinks` の指定により、実際に収集される内容が変わります（収集方式参照）。

- 非対象:
  - デバイス、FIFO、ソケットなどの特殊ファイルは候補に含めません。
