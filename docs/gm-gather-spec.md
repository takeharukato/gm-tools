# gm-gather 仕様

本書は `gm-gather` コマンドの実際の挙動を権威仕様として記述する。共通仕様や用語は `docs/common-spec.md` を参照のこと。

## 引数とオプション


- `SRC...` : 1 つ以上のリモートパスまたはパターン。
- `DEST`   : ローカル保存先ディレクトリ。必須。

### 位置引数

| 引数 | 説明 |
| ---- | ---- |
| `SRC...` | リモート側の取得元。リテラル/正規表現/チルダ展開の規則は「パスと正規表現仕様」を参照。最低 1 件必要。 |
| `DEST` | ローカル側の出力ディレクトリ。相対指定は起動時のカレントディレクトリで絶対化し、`~` や `~user` 形式は無効。 |

### オプション一覧 (man スタイル)

| オプション | 説明 |
| ----------- | ---- |
| `-H`, `--hosts` *FILE* | ホストファイルを指定。既定では `hostfile` を読み込み、空行・先頭 `#`・行末コメントを無視する。 |
| `-u`, `--user` *USER* | リモートでの参照ユーザ。`SRC` の `~/` 展開や権限評価で利用。既定は実行ユーザ。 |
| `-s`, `--ssh-user` *USER* | SSH ログインに用いるユーザ。省略時は `--user` と同じ。sudo を自動使用するかの判定に影響する。 |
| `-P`, `--port` *PORT* | SSH ポート番号。既定は 22。 |
| `-K`, `--key` *PATH* | SSH 秘密鍵ファイルのパス。未指定時は OpenSSH と同様の既定設定を利用。 |
| `-W`, `--password` *PASS* | SSH パスワード。コマンド履歴に残るため鍵認証が推奨される。 |
| `-T`, `--timeout` *SEC* | SSH セッションおよびリモートコマンドのタイムアウト秒。既定は 30 秒。 |
| `-S`, `--strict-host-key-checking` | 有効にすると未知のホスト鍵を拒否し、known_hosts に無いホストへは接続しない。省略時は未知の鍵を自動登録する。 |
| `-j`, `--parallel` *N* | ホスト単位の並列数。1 以上に丸められ、既定値は 4。 |
| `-n`, `--dry-run` | 取得計画のみ構築し、転送は行わない。ログの要約のみ出力。 |
| `-v`, `--verbose` | 追加のデバッグログを有効化。dry-run 時も適用。 |
| `--pack` | ホスト単位でリモートに tar.gz を生成し、1 回のダウンロードでまとめて展開する。省略時は SFTP 逐次転送。 |
| `--follow-symlinks` | `--pack` 使用時にリモートのシンボリックリンクを辿って実体を収集しようと試みる。SFTP モードでは候補から除外したまま。 |
| `-x`, `--sudo-collect` | `--pack` 経路でのファイル列挙や tar/gzip 実行を常に `sudo -n` で行う。 |
| `--no-sudo-collect` | `--pack` 経路でも `sudo` を使用しない。 |

`--sudo-collect` と `--no-sudo-collect` をどちらも省略した場合、SSH ログインユーザと対象ユーザが異なるときのみ `sudo -n` が自動的に有効になる。

### オプション詳細

- SSH 接続は Paramiko を利用して確立し、プログラム終了時まで再利用する。鍵ファイルやパスワードは Paramiko にそのまま渡される。
- `--timeout` の値は、リモートのホームディレクトリ検出、一時アーカイブ作成、リモートコマンド実行、後片付けなど、すべてのネットワーク操作で共通のタイムリミットとして使われる。
- `--pack` 指定時は、ホストごとに一度だけリモート側で tar.gz を作成し、それをダウンロードして展開する。SFTP モードでは収集対象ごとに逐次ダウンロードする。
- `--follow-symlinks` は `--pack` と併用した場合にのみ意味があり、対応する tar コマンドがあればシンボリックリンクのリンク先を取り込む。SFTP モードではシンボリックリンクは常に除外される。
- `--dry-run` では収集対象を列挙して件数を集計するが、ファイル転送は行わない。終了コードは 0 となる。
- `--parallel` はホスト単位の並列度として使用され、指定した数だけスレッドを起動する。ただし 1 ホスト内のファイル処理は逐次実行となる。

## パスと正規表現仕様

- `SRC` は以下の形式に対応する。
  - `/...` : UNIX 系の絶対パス。収集時にはそのまま利用する。
  - `X:/...` または `X:\...` : Windows のドライブ絶対パス。ドライブ文字の後はスラッシュ区切りに整形して扱う。
  - `~/...` : `--user` で指定したリモートユーザのホームディレクトリに展開する。
  - 相対指定 : 正規表現記号が現れる手前までを対象ユーザのホームディレクトリ直下に連結して解釈する。`..` でホームより上位へ出ようとするとエラーとして該当パターンを除外する。
- `~` 単独、`~user`、`~user/...` はいずれも無効であり、「bare tilde is not allowed」「tilde with username is not supported」を表示して終了する。
- 正規表現かどうかは `^` や `[]` などの記号の有無で判定し、`.` だけでは正規表現扱いにならない。
- 正規表現として扱う場合は、記号が現れる直前までを走査起点ディレクトリとし、その配下のファイルやディレクトリ名をスラッシュ区切りの相対パスとして正規表現に照合する。Windows であっても `/` 区切りで評価する。
- 走査起点が存在しない場合、その `SRC` は収集対象から除外される。

## SRC と DEST の解釈およびレイアウト

- ホストファイルに記載された各ホストについて、以下の手順で収集計画を組み立てる。
  1. SSH と SFTP のセッションを開き、対象ユーザのホームディレクトリを調べる。
  2. `SRC` で指定されたパターンを解釈し、該当するファイルやシンボリックリンクを列挙する。
  3. 通常ファイルのみを収集対象に追加し、デバイスファイルやパイプなどは除外する。
- `DEST` には `~` や `~user` を含めることはできない。相対パスを指定した場合は、実行時のカレントディレクトリを基準に絶対パスへ変換する。
- 保存レイアウトは次の形で構成される。

  ```text
  DEST/<SANITIZED_HOST>/<REMOTE_PATH_NORMALIZED>
  ```

  ここで `<SANITIZED_HOST>` は、ホスト名に含まれる禁止文字をアンダースコアへ置き換え、先頭のドットを取り除いたものを使用する。`<REMOTE_PATH_NORMALIZED>` はリモートの絶対パスをスラッシュ区切りに整形し、Windows のドライブ名は `C_/` のように変換する。UNC パスもスラッシュ区切りへ揃える。

## 転送方式

### SFTP 逐次 (既定)

- 収集対象ごとに SFTP の `get` を呼び出してファイルをダウンロードする。ディレクトリは中身を転送せずスキップする。
- ダウンロード前にローカル側の保存先ディレクトリを必要に応じて作成する。
- 権限や更新時刻などのメタデータは Paramiko の既定動作に従い、完全な復元は保証されない。

### `--pack`

- ホストごとにリモート側で一時的な tar.gz を作り、そのファイルをダウンロードして該当ホスト用ディレクトリへ展開する。
- 利用可能な tar コマンドの種類を調べ、`--follow-symlinks` が有効ならシンボリックリンクを実体として取り込むオプションを付与する。対応していない種類の場合はリンクとして取得する。
- 展開時はパストラバーサルを防ぐために危険なパスを拒否し、親ディレクトリがシンボリックリンクの場合はそのファイルをスキップする。
- GNU tar のハードリンク情報は展開時に通常ファイルへ展開される。可能な範囲で元ファイルのパーミッションと更新時刻を復元する。
- リモートに残った一時アーカイブは `sudo -n rm -f`、`rm -f`、`true` の順に試みて削除する。

## 転送対象の相違

| 項目 | SFTP | `--pack` |
| ---- | ---- | -------- |
| 対象とする通常ファイル | リモートで通常ファイルと判定できたものだけを取得。 | アーカイブに含まれる通常ファイルと、GNU tar が保持するハードリンクを通常ファイルとして復元。 |
| ディレクトリ | 対象リストには含めるが中身は転送しない。必要に応じて親ディレクトリをローカルに作成。 | アーカイブ展開時にディレクトリを再現。親ディレクトリがシンボリックリンクなら該当ファイルをスキップ。 |
| シンボリックリンク | 常に転送しない。`--follow-symlinks` を指定しても通常ファイル化されない。 | `--follow-symlinks` 指定時のみ候補に含まれ、リンクの実体を取り込めた場合に通常ファイルとして復元。対応しない tar コマンドや失敗時はリンク自体を除外。 |
| デバイス/FIFO/ソケット | 列挙段階で除外。 | 展開時の安全性チェックで除外。 |

## シンボリックリンクと `--follow-symlinks`

- フラグ未指定時
  - パターン展開段階でシンボリックリンクは収集対象から除外される。
  - `--pack` を使用しても、リモートで作成する tar にはシンボリックリンクが含まれず、ローカルでも生成されない。
- フラグ指定時
  - `--pack` と併用した場合のみ効果があり、リンクを実体として取り込める tar コマンドであれば通常ファイル化して保存する。
  - SFTP モードではシンボリックリンクが検出されても対象リストに加えないため、挙動に変化はない。
  - 親ディレクトリがシンボリックリンクの場合、アーカイブ展開時に警告を出して該当項目をスキップする。

## sudo の利用条件

- `--sudo-collect` を指定すると、リモートのファイル列挙や tar/gzip 実行に常に `sudo -n` が使われる。
- `--no-sudo-collect` を指定すると、`sudo` は一切使用しない。
- どちらも指定しない場合は、SSH ログインユーザと収集対象ユーザが異なるときだけ `sudo -n` が自動的に有効になる。昇格後のユーザは通常 root であり、sudoers 設定に依存する。
- ローカル側で `sudo` を用いる処理は存在しない。

## SELinux について

`gm-gather` は SELinux ラベルの検出・復元機能を備えておらず、`--selinux` オプションも存在しない。リモートホストが SELinux を使用していても、収集結果のファイルには SELinux コンテキストは付与されない。

## メタデータ復元条件

- 所有者・グループ: SFTP と `--pack` のいずれもローカルユーザでファイルを作成するため、復元しない。
- アクセス権: SFTP では Paramiko の既定動作 (ローカルの umask 依存)。`--pack` では tar に記録されたモードを可能な範囲で適用し、失敗しても警告せず継続する。
- 更新時刻: SFTP では保証しない。`--pack` では `utime` により設定を試みる。
- 拡張属性/ACL: いずれの方式でも復元しない。

## 並列処理 (`--parallel`)

- ホスト単位でスレッドを割り当て、最大でも `--parallel` で指定した数だけ同時に処理する。各ホスト内のファイル転送は逐次で行う。
- 並列度は 1 未満を指定しても 1 に切り上げられる。大きい値を指定するとスレッド数が増えるため、リモートホストの負荷やネットワーク帯域に注意が必要である。

## エラーメッセージと終了コード

代表的なメッセージと終了コードは次の通り (メッセージは gettext で翻訳される)。

| メッセージ (msgid) | 発生条件 | 終了コード |
| ------------------- | -------- | ---------- |
| `"At least one SRC and a DEST are required."` | 位置引数が不足している。 | 4 |
| `"bare tilde is not allowed"` | `SRC` または `DEST` に `~` を単独で指定した。 | 4 |
| `"tilde with username is not supported"` | `SRC` または `DEST` に `~user` 形式を指定した。 | 3 |
| `"No hosts found in hosts file."` | ホストファイルから有効なホストが得られない。 | 1 |

- 実行中の転送でエラーが発生すると、ホスト単位の集計でエラー件数が 1 以上と記録され、プロセスの終了コードは 2 になる。
- `--dry-run` で計画生成のみ行った場合は、常に終了コード 0 を返す。

## シグナル受信時の動作

- SIGINT/SIGTERM を受信すると中断フラグが立ち、新しいホストの処理は開始せず、進行中のホストにはキャンセルを通知する。
- 中断後は `"Interrupt requested; cancelling remaining transfers…"` という警告ログを出力し、成功したホストの有無に応じて終了コード 0 または 2 を返す。
- 終了時には開いている SSH/SFTP セッションを閉じ、ローカルの一時ディレクトリを削除し、最後に集計結果を出力する。

## 制限と注意事項

- `SRC` の正規表現は Python `re` の仕様に従うため、ロケールに依存する挙動を持つメタ文字が含まれる場合がある。必要に応じて明示的なフラグを付与すること。
- `--pack` を使用するにはリモートに `tar` と `gzip` がインストールされている必要がある。利用できない場合はエラーで終了する。
- `--follow-symlinks` は `--pack` と組み合わせた場合のみ効果があり、リモートの tar コマンドがリンクの実体化をサポートしない場合はシンボリックリンクを取得できない。
- ローカル保存先に既存ファイルがある場合は上書きされる。差分取得機能は無い。
- `--password` はコマンドラインで指定するためシェル履歴に残る可能性がある。取り扱いに注意すること。
- Windows ホストの UNC パス (`//srv/share` など) も指定できるが、保存時にはアンダースコアを含むパスに正規化される。
- 長時間の収集中に SIGINT を送信すると一部のホストだけが収集済みとなる場合がある。ログと出力内容を確認し、必要なら再実行すること。
- 取得したファイルの整合性チェック (ハッシュ検証など) は実装していない。必要に応じて別途確認すること。
- 取得したファイルの整合性チェック (ハッシュ検証等) は実装していない。必要に応じて別途確認すること。
