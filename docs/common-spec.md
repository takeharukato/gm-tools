# gm-tools 共通仕様

本書は `gm-gather` と `gm-scatter` に共通する仕様と運用上の注意をまとめます。各コマンド固有の仕様はそれぞれの仕様書を参照してください。

- `gm-gather` 仕様: ./gm-gather-spec.md
- `gm-scatter` 仕様: ./gm-scatter-spec.md

## 記法・方針

- 矢印表記は「 => 」(スペース=>スペース) を用います。
- 用語は「終了コード」に統一します。
- 共有事項は本書に集約し、各仕様書から参照します。

## ホストファイル形式

ホストファイルとは、本ツールで操作の対象となるリモートホスト群を定義するファイルです。

- 1 行に 1 ホスト名/IP を記述します。
- 空行、`#` で始まる行、または「タブ/空白に続く `#` 以降」はコメントとして扱います。
- 既定パスは `hostfile` です。

### ホストファイルの例

```text
# サーバ群を示すコメント行
web01.example.com
web02.example.com    # 任意の注記（例: 設置場所）

10.0.0.15
```

例の各行の意味を説明します。

- `# サーバ群を示すコメント行`: コメント行として扱い、読み取り時に無視します。
- `web01.example.com`: FQDN をホストとして解釈します。
- `web02.example.com    # 任意の注記（例: 設置場所）`: `#` 以降はコメントとして無視し、`web02.example.com` をホストとして解釈します。
- 空行はコメントとして扱い、無視します。
- `10.0.0.15`: IPv4 アドレスをホストとして解釈します。

## SELinux 対応ホストの判定基準

対応可否の判定基準は次のとおりです。

- selinuxfs の存在が確認できる必要があります（ `/sys/fs/selinux` が存在する必要があります）。
- `restorecon` コマンドが利用可能である必要があります（ `command -v restorecon` が成功する必要があります）。

### SELinux 対応に必要なパッケージについて

- RHEL/AlmaLinux/CentOS 系: `policycoreutils` に `restorecon` が含まれます。
- Debian/Ubuntu 系: `policycoreutils` に `restorecon` が含まれます。
- SELinux 無効ホストでは `--selinux=policy` はエラー、`auto` は無処理です。

## 終了コードの概念

終了コードはプロセスの成否を表します。
値と意味の詳細定義は各コマンド仕様を参照してください。

## パス区切り文字の扱い

- パス区切り: SFTP 経路のパス区切りは常に `/` です。リモート上でシェル経由の操作を行う場合は各 OS の区切り文字（Windows は `\`、Unix 系は `/`）に従います。
- Windows ドライブレター (`X:/...`):
  - この形式は「Windows の絶対パス」として扱います。
  - 非Windows の実行環境でローカルパスとして指定した場合はエラーになります。非Windows のリモートに対する SRC として指定した場合は一致せずにスキップされます。非Windows では `/...` または `~/...` を使用してください。

- Windows UNC (`\\\\server\\share\\...`):
  - Windows 上では「絶対パス」として扱います。非Windows 実行環境でローカル SRC に指定した場合はエラーになります（scatter）。
  - レイアウト正規化: ローカル => リモート配置（scatter）では `\\\\server\\share\\p` を `server/share/p` に正規化して `DEST/<rel>/...` を構成します。リモート => ローカル保存（gather）でリモート絶対パスが `//...` で始まる場合は、先頭の空セグメントを `_` として保持します（例: `//a//b/` => `_/a/_/b`）。

## ホスト名, パス名のDESTディレクトリ内保存用表現への変換規則について

- ホスト名の保存用表現:
  - 先頭が `.` の場合は先頭を `_` に置換します。
  - 英数字・ドット (`.`)・ハイフン (`-`)・アンダースコア (`_`) 以外の文字は `_` に置換します。
  - パス区切りや制御文字など、ファイル名として不適切な文字は同様に `_` に置換されます。
- リモート絶対パスの「保存用の相対表現」:
  - 先頭のルート部分（例: `/` や `C:/`）を取り除き相対にします。
  - 区切りは `/` に統一します。空セグメント（`//` による）は 1 セグメントの `_` として表します（例: `//a//b/` => `_/a/_/b`）。
  - Windows ドライブレターを含む場合は、先頭要素のコロン（`C:/` の `:`）を `_` に置換します（例: `C:/x/y` => `C_/x/y`）。
  - 各パス要素内の英数字・ドット・ハイフン・アンダースコア以外の文字は `_` に置換されます。

## 正規表現とチルダの解釈

### 正規表現の検出

メタ文字である `^$*+?{}[]\|()` のいずれかを含むパスを指定した場合, 対象のパスを正規表現付きのパスとして扱います。`.` は正規表現検出対象メタ文字としては、扱われません（例: `foo.bar` はリテラルとして扱います）。

### ルート相対パス文字列について

実際の絶対パス（または HOME を起点として絶対化したパス）から先頭のルート部分（例: POSIX の `/`、Windows の `C:/`、UNC の `//server/share` など）を取り除き、区切りを `/` に統一した文字列を本書では, 「ルート相対パス文字列」と呼称します。

本ツールは, ルート相対パス文字列中から指定された正規表現文字列を検索し, 正規表現にマッチする部分を含むパスを、転送候補として扱います。

ルート相対パスへの変換例を以下に示します。

- POSIX(Linux/BSDなど): `/var/log/a.log`  =>  `var/log/a.log`
- Windows ドライブ: `C:/Windows/Logs/a.log`  =>  `Windows/Logs/a.log`
- Windows UNC: `//server/share/dir/file.txt`  =>  `server/share/dir/file.txt`
- HOME 起点（相対指定を絶対化後）: `~/app/logs/x.txt`  =>  `app/logs/x.txt`

### gm-gather/gm-scatterでの正規表現とチルダの解釈について

- gm-gather（SRC=リモート, DEST=ローカル）
  - SRC（リモート）:
    - 絶対パス指定: `/...` は UNIX 絶対、`X:/...`/`X:\...` は Windows 形式の絶対として扱い、`X:/...` に正規化します。
    - `~/`: `--user` のリモート HOME に展開します。チルダ単独(`~`)やユーザ名付きのチルダ(`~user`) は受け付けません。
    - 相対パス指定: `--user` のリモート HOME を起点に結合します。パス部に `..` を含む指定は拒否します。正規表現メタ以降は無改変で保持します。
    - 正規表現評価: ルート（`/` や `C:/` など）より後ろのルート相対パス文字列に対して部分一致で評価します（Python の `re.search`を用いて評価）。評価対象はファイルです。ディレクトリをリテラル指定した場合(正規表現のメタ文字を含まない場合)は、その配下の通常ファイルを列挙します（シンボリックリンクの扱いは`--follow-symlinks`オプションに従います）。
      - パス区切り文字の扱い: リモート探索では正規表現中の区切りは常に `/` を用います（Windows でも `C:/...` かつ `/` 区切りになります）。
      例: `var/log/.*\\.log` は `var/log/a.log` (Windowsホスト上の`var\log\a.log`) に一致します。`var\\log\\.*\\.log`と記載することはできません。
  - DEST（ローカル）:
    - `~/`: 実行ユーザーの HOME に展開します。チルダ単独(`~`)やユーザ名付きのチルダ(`~user`) は受け付けません。相対パス指定時は実行時のカレントディレクトリからの相対パス指定として解釈し、絶対パスに変換します。
    - 保存先レイアウト: `DEST/<ディレクトリ内保存用表現変換後のホスト名>/<ディレクトリ内保存用表現変換後のルート相対パス文字列>` に保存します（例: `C:/x/y` は `C_/x/y`）。

- gm-scatter（SRC=ローカル, DEST=リモート）
  - SRC（ローカル）:
    - 絶対パス指定: `/...` はローカル絶対。`X:/...` は Windows 上のみ有効で、非 Windows ではエラーになります。
    - `~/`: 実行ユーザーの HOME に展開します。チルダ単独(`~`)やユーザ名付きのチルダ(`~user`) は受け付けません。
    - 相対パス指定: 実行時のカレントディレクトリからの相対パス指定として解釈し、絶対パスに変換します。
    - 正規表現評価: ルートより後ろの「ルート相対パス文字列」に対して部分一致で評価します（Python の `re.search`）。正規表現モードでは通常ファイルを列挙します（ルート自身が空相対にマッチする場合はルートも含まれることがあります）。メタ無しのリテラル指定で存在する場合は、そのパス（ファイル/ディレクトリ）を候補とします。非 pack 時はディレクトリは転送対象から除外します。
      - パス区切り記法: ローカル探索は OS の区切りで評価します（Linux/macOS は `/`、Windows は `\\`）。Windows では正規表現中も `\\` 区切りで記述します。例: `foo\\.*` は `foo\\a.txt` に一致し、`bar\\a.txt` には一致しません。
  - DEST（リモート）:
    - 絶対パス指定: `/...` は絶対、`X:/...` も絶対として受理します。
    - `~/`: `--user` のリモート HOME に展開します。チルダ単独(`~`)やユーザ名付きのチルダ(`~user`) は受け付けません。
    - 相対パス指定: `--user` のリモート HOME を起点に解決します。

- パス区切り文字: リモート探索（SFTP 経路）は OS に関わらず `/` 区切りで評価します（Windows でもドライブは `C:/...`、区切りは `/`）。`--pack` 指定時（sudo の有無に関わらず）も、正規表現の評価対象となる「ルート相対パス文字列」は `/` 区切りに正規化して評価します。なお、実際に扱うリモートの絶対パス表記は列挙経路により OS 依存の区切りになる場合がありますが（例: Windows の `--pack`+sudo では `C:\...`）、正規表現の評価は常に `/` 区切りです。ローカル探索は OS の区切り文字で評価します（Linux/macOS は `/`、Windows は `\\`）。

## 候補列挙（探索経路と含まれる対象）

本節は、正規表現/チルダ展開後にどのパスが候補として列挙されるかの共通挙動を示します。

- 走査経路の選択:
  - `--pack` を指定し、かつリモート側で権限昇格を伴う走査が有効な経路では、リモート上でルート配下を走査します。ルート相対パスに対して正規表現を部分一致で評価します（Python の `re.search`）。
  - 上記以外の経路では、SFTP でルート配下を走査します。ルート相対パスに対して正規表現を部分一致で評価します（Python の `re.search`）。

- ディレクトリのリテラル指定（メタ無しで SRC がディレクトリのとき）:
  - その配下の「通常ファイル」を候補として列挙します。ディレクトリ自身は候補に含めません。

- シンボリックリンク（ファイルへのリンク）の候補化:
  - `--pack` 未指定: 候補に含めません（通常ファイルのみ）。
  - `--pack` 指定時: リンクそのものを候補に含めます。実際の転送内容は次節の転送方式・リンク扱いに従います。

- ディレクトリへのシンボリックリンク:
  - SFTP の型判定によりディレクトリとして見える場合があり、その場合は配下を走査することがあります（ディレクトリリンク自体を特別扱いはしません）。

- 非対象:
  - デバイス、FIFO、ソケット等の特殊ファイルは候補に含めません。

## 転送方式の詳細（SFTP 逐次 と pack）

- SFTP 逐次（`--pack` 未指定）:
  - 対象: 候補のうち「通常ファイル」のみを 1 件ずつ転送します。
  - 非対象: ディレクトリ、シンボリックリンク、デバイス/FIFO/ソケット等は転送しません。

- pack（`--pack` 指定: リモートでアーカイブを作成して 1 回で取得・展開）:
  - 収集単位: ホストごとに 1 度だけ打ち上げ・取得・展開を実行し、ローカルに通常ファイルを復元します。
  - ディレクトリ: 必要なディレクトリは展開時に作成します。親チェーンにシンボリックリンクがある場合は安全のためスキップします。
  - シンボリックリンク（ファイルへのリンク）の扱い:
    - `--no-follow-symlinks`（既定）: リンクはアーカイブ内でリンクとして保存され、ローカル展開ではシンボリックリンクを作成しません。結果として、リンクのみが一致している場合はローカルにファイルは生成されません。
    - `--follow-symlinks`: 可能な環境ではリンク先の実体を収集対象として扱い、ローカルには通常ファイルとして復元します。環境によりリンク先の実体化が行えない場合は、上記の既定と同様にリンクとして保存され、ローカルには生成されません。

### pack 時のハードリンクの扱い

- GNU tar の最適化によりハードリンクが記録されている場合、ローカル展開時は「通常ファイル」として復元します（デマテリアライズ）。
- 復元手順:
  - 既に抽出済みのソースファイルがあれば、その内容を複製して通常ファイルを作成します。
  - 未抽出の場合は、アーカイブ内の同名メンバー（通常ファイル）があればその内容から作成します。
  - いずれも不可能な場合は警告の上スキップします。
- 成功した復元は抽出件数（extracted_count）に加算します。

## シグナルと協調停止 (Graceful Stop)

本ツールでは、SIGINT/SIGTERM シグナルを受け付けた際（例: Ctrl-C 押下時）に協調停止（Graceful Stop）処理に移行します。
協調停止処理に移行すると、安全な中断点で実行中の処理を停止し、以降のホスト/ファイルの転送を取りやめ、ローカルホストとリモートホストで作成した一時ファイルの削除を試みます。
また、協調停止前の動作に応じて終了時の集計処理を行います。

## 出力ログ仕様

### ログの書式

本ツールでは、動作時のログを以下の形式で出力します。

```text
<timestamp> level=<level> host=<host> op=<op> phase=<phase> trial=<n> processed=<n> total=<n> [warnings=<n>] [errors=<n>] [duration=<sec>] [seq=<n>]
```

固定キーとして `timestamp`、`level`、`host`、`op`、`phase`、`trial`、`processed`、`total` を出力した後に、任意キーとして `warnings`、`errors`、`duration`、`seq` を出力します。

なお, 各ログ出力はホスト単位で集約され、並列実行時でもログの行が途中で混ざったり崩れたりしません。

#### 各キーの意味と例

- `timestamp`: ISO-8601 の時刻を示します。タイムゾーンとミリ秒を含みます。例: `2025-11-19T12:10:00.000+09:00`
- `level`: ログレベルを示します。
  - `DEBUG`: 進捗など詳細情報。標準出力。例: `processing` 行。
  - `INFO`: 通常情報。標準出力。例: `host start`/`host done`/`summary`。
  - `WARNING`: 警告。標準エラー出力。
  - `ERROR`: エラー。標準エラー出力。
  - `CRITICAL`: 致命的エラー。標準エラー出力。
- `host`: 対象ホスト名を示します。
  - ホスト単位ログ: 対象ホスト名（例: `db01`）を出力します。
  - 集計ログ: `-` を出力します（全体集計であることを示します）。
- `op`: 操作種別を示します。
  - `gather`: リモートホストからローカルホストへの転送を意味します。
  - `scatter`: ローカルホストからリモートホストへの転送を意味します。
- `phase`: フェーズを示します。
  - `start`: 当該ホストの処理を開始したことを示します。
  - `processing`: 当該ホストの処理が進行中であることを示します（進行行）。
  - `done`: 当該ホストの処理が完了したことを示します (完了行)。
- `trial`: 当該ホストでこれまでに試行した件数（成功・失敗を含みます）を示します。開始時は `0` で、処理の進行に伴い増加します。正常に転送が完了した場合の完了行(`done`)では計画件数(`total`)と一致します。例: `356`
- `processed`: 当該フェーズまでに処理済みの件数を示します。例: `220`
- `total`: 当該ホストに対して計画された総転送件数を示します。例: `356`
- `warnings`: 警告件数を示します。主に完了行(`done`)および集計行(`summary`)に表示されます。例: `1`
- `errors`: エラー件数を示します。主に完了行(`done`)および集計行(`summary`)に表示されます。例: `0`
- `duration`: フェーズまたはホスト処理の所要時間(秒)を示します。ホストの完了行(INFO)にのみ表示され、集計行(`summary`)には表示されません。例: `8.2`
- `seq`: ログ行の逐次番号を示します。`--verbose` オプション指定時の進行行(`processing`)にのみ表示されます。

##### ホストの完了行の意味

ホストの完了行とは、特定ホストの処理が完了した時点で出力される INFO ログを指します。`phase` は `done`、`host` は対象ホスト名となり、`warnings`・`errors`・`duration` が併記されます。これは実行全体の集計ではなく、当該ホスト 1 台に関する最終的な件数と結果を示します。

##### 集計行(`summary`)の表示内容

集計行は、全ホストの処理が終了した後に 1 回だけ出力される INFO ログです。表示内容は次のとおりです。

- 出力タイミング: 全ホストの処理終了後に 1 回出力します。
- `level`: `INFO` を出力します。
- `host`: `-` を出力します（全体集計であることを示します）。
- `op`: 実行中の操作種別（`gather` または `scatter`）を出力します。
- `phase`: `done` を出力します。
- `trial`: 全ホストの試行件数の合計（各ホストの `trial` の総和）を出力します。
- `processed`: 全ホストの処理成功件数の合計（各ホストの `processed` の総和）を出力します。
- `total`: `trial` と同じ値を出力します。
- `warnings`: 全ホストの警告件数の合計を出力します。
- `errors`: 全ホストのエラー件数の合計を出力します。
- `duration`: 出力しません。
- `seq`: 出力しません。
- `msg`: `summary` を出力します。

### ログ例

```text
2025-11-19T12:10:00.000+09:00 level="INFO" host="db01" op="scatter" phase="start" trial="0" processed="0" total="356" msg="host start"
2025-11-19T12:10:02.345+09:00 level="DEBUG" host="db01" op="scatter" phase="processing" trial="10" processed="128" total="356" seq="5" msg="processing"
2025-11-19T12:10:08.200+09:00 level="INFO" host="db01" op="scatter" phase="done" trial="356" processed="356" total="356" warnings="1" errors="0" duration="8.2" msg="host done"
2025-11-19T12:10:08.250+09:00 level="INFO" host="-" op="scatter" phase="done" trial="356" processed="356" total="356" warnings="1" errors="0" msg="summary"
```

## メッセージのローカライゼーション対象範囲について

- ユーザー向けのヘルプや警告・エラーメッセージはローカライズされます。
- 構造化ログのキーおよび `msg` の語句（例: `host start`、`processing`、`host done`、`summary`）はローカライズの対象になりません。キー順は固定です。

## 依存パッケージ

### ローカルホスト (実行環境)

- Python ライブラリとして `paramiko` を使用します。

OS パッケージでの導入例:

```shell
# RHEL/AlmaLinux/Rocky
sudo dnf install -y python3-paramiko

# Debian/Ubuntu
sudo apt-get update && sudo apt-get install -y python3-paramiko
```

pip での導入例:

```shell
# 単体インストール
python3 -m pip install --user paramiko

# requirements.txt を用いる場合 (ファイルに "paramiko" を記載)
python3 -m pip install -r requirements.txt
```

### リモートホスト (必要に応じて)

- `tar` (GNU tar 推奨) が必要です。
- `setfacl` (ACL 復元に必要) が必要です。
- `setfattr` (xattr 復元に必要) が必要です。
- `restorecon` (SELinux ラベル再適用に必要) が必要です。
